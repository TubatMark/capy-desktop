# A3 durable worker, cancellation and resource controls

Next requests persist work and read committed SQLite snapshots. The app/dev sidecar owns execution, posting and discovery. Worker records are namespaced documents in the A2 database, with identity/revision deduplication, queue capacity, checkpoints, attempts, cancellation, owner, generation, lease expiry and registered process groups. A separate durable service election makes additional app/dev workers stand by; losing election cancels active execution without terminating Next or the standby worker.

The worker invokes the existing JobManager pipeline and B2 Studio adapters. This is the production execution path, including metadata, captions/transcript, selection/review, segment download, render, translation, replacement, publication metadata, thumbnails, asset probe/proxy and source-range fetch. Metadata/captions/selection/segments checkpoints let media retries skip completed stages. Legacy inflight jobs are seeded once when no durable work exists, while terminal cancellation is respected. Failed pool members now propagate instead of silently completing interrupted downloads. UI operations that require a response await the durable result while computation remains in the sidecar. SSE polls committed snapshots across processes and health reports heartbeat, active stages, limits and blocking reasons.

Each generation writes in its own workspace. Completed outputs are promoted synchronously inside the same SQLite transaction that validates task and service ownership; canonical originals are never the target of an unfenced asynchronous media write. Job revision comparison and input fingerprints reject stale work after user edits. Completed assets are retained across retries/cancellation. Job, queue, watch, account refresh and learned estimate writes run through the fence. A1 publication eligibility still runs immediately before upload, retaining its bound destinations, approved text and delivery options. Interrupted publication without remote acknowledgement becomes needs_action; acknowledged resumable progress remains available for a gated retry.

Detached subprocess groups carry an execution token and recorded start identity. Cancellation/deadline handling awaits TERM/KILL completion before releasing the operation. Expired-owner takeover terminates only verified owned groups before replacement. Reused PID/group numbers alone never authorize a signal. HTTP operations share cancellation and finite deadlines. Subprocess output is bounded. The worker executes one task/stage at a time; expensive stages check available disk reserve and queue admission caps outstanding tasks. AI provider admission and reservation use A4's single ledger, with stable job/input context. AI exhaustion blocks spending; deterministic editor stages require neither an AI allowance nor posting accounts/cloud access.

Electron supervises the worker independently of its standalone Next server, with bounded restart delay. Dev/start use the same sidecar separation. Packaging places worker.cjs beside Resources/server/node_modules so the external Claude SDK resolves from the standalone server tree. The explicit worker:service install/start/status/stop/uninstall CLI creates a disabled launchd definition on install; start explicitly enables it, and stop disables it. No launchd command was executed and no background service was installed/enabled.

Scope decisions: the legacy poster-lock helper and platform context type remain compatibility interfaces; production posting uses the SQLite service owner rather than a second filesystem lock, and bounded HTTP fetch is supplied through the existing platform context. A4 requested fail-closed review persistence: failed reviews now remain unselected with needs_review, and the strict A2 validator accepts that canonical verdict. The regression reloads it through authoritative storage. Shared JobRecord is canonical in lib/studio/types.ts. package/lock also include controller-installed exact @playwright/test 1.64.0 for B2 browser tooling.

# Studio rendering: staged ffmpeg fallback

2026-10-10 decision: defer Hyperframes adoption. No tested Hyperframes version is pinned and no dependency or packaging change is justified. The reconnaissance in `.superpowers/renderer-recon.md` records official upstream package/license evidence; documentation establishes potential capability, not compatibility.

The implemented `compileProject(ProjectDocument, AssetRef[])` returns a revision-bound RenderPlan containing rational fps, integer frames, resolved local paths and SHA-256 hashes, source mapping, canvas, explicit silent audio policy and renderer version. `renderProject(plan, signal)` produces an immutable temporary artifact and checks decoded frame count. Cancellation/failure removes its own output directory. Callers own successful artifact retention/publication. Preview must consume that same rendered artifact; UI proxy wiring is pending.

The supported foundation is contiguous silent video cuts, deterministic CFR source sampling, letterbox fit, even output dimensions and rational constant fps. Missing/changed assets, mismatched source mapping, invalid ranges, gaps, overlaps, actual probed source audio, captions, text/image overlays, transforms, speed, audio envelopes/tracks and future transition/ducking fields are rejected before rendering. This is a staged contract foundation, not the completed R1 renderer. B3/B4 must extend validated canonical operations and rendering together.

A separate synthetic ffmpeg experiment actually rendered 900 frames at 30 fps with two crossfades, local-font caption/static overlay, 48 kHz music and dialogue-triggered ducking. It demonstrates available local filters; it does not demonstrate these features through the canonical compiler. Run `node test/fixtures/renderer/experiment.mjs`; outputs stay in an OS temporary directory. Reference frames cover transition edges and three midpoints. Recorded audio markers are 220 Hz music throughout and 1000 Hz dialogue from 10–15 seconds, with compressor 100 ms attack / 300 ms release. Decoded PCM Fourier windows measure music amplitude 0.12457 before, 0.04276 during and 0.12494 after dialogue: -9.287 dB attenuation. The requested 12 dB reference is not met; decoded marker timing remains unmeasured.

Review correction: export snapshots the caller plan synchronously before its first await, then validates its dimensions/fps/frame count. Source silence is verified against actual ffprobe streams during compile and rechecked at render; optional AssetRef metadata cannot authorize audio loss. This bounded adapter requires matching source/output CFR (average and nominal rates must agree, and every decoded presentation timestamp must match the zero-origin rational cadence within half a native timebase tick); mixed-rate/VFR support remains deferred. Integer microsecond source starts are legitimate: start sampling uses exact rational ceiling `ceil(sourceInUs * numerator / (1e6 * denominator))`, selecting the first source CFR frame at or after the requested boundary. It then takes exactly durationFrames source frames and rebases their timestamps. A fractional start shifts sampling by less than one source frame; no claim is made that arbitrary source microseconds identify an exact frame boundary. Final cancellation is checked after hashing and immediately before artifact publication, inside cleanup protection.

Cadence validation reads actual decoded best-effort presentation timestamps, compares each to its absolute ordinal rational timestamp using integer arithmetic, and rejects missing timestamps, nonzero origins outside tolerance, variable spacing and cumulative drift. Aggregate frame rates alone never authorize CFR sampling. The bounded synchronous compile probe has a 64 MiB result cap and fails closed when probing exceeds it; a streaming/background probe is a later performance improvement.

## B4 rich normalized renderer

B4 adds `src/studio/ffmpeg-adapter.ts` behind the durable Studio worker. The earlier bounded `compileProject` / `renderProject` contract and its CFR ceiling regression remain unchanged. Studio exports use `compileNormalizedProject` / `renderNormalizedProject`, immutable revision snapshots and exact artifact IDs. The normalized preview and download consume the same registered bytes. Local export requires no account; preparing a review draft feeds the existing A1 publication evaluator with real project/revision/render identity.

The rich adapter supports mixed fps/VFR, display rotation, SDR normalization, cuts/gaps/crossfades, still/text layers, captions, transforms, crop/fit/blur/basic color, and B3 exact audio spans/gain/ducking. It samples video nearest the requested source clock rather than rebasing to the first eligible native frame: at 24 fps, a 1 ms trim otherwise shifts a native frame by 40.67 ms, exceeding the 30 fps output-frame allowance. This explicitly reviewed B4 policy is recorded in each artifact's `normalizationPolicy`; it does not change the earlier bounded adapter's policy. Audio is resampled/mixed at 48 kHz against the same requested clock. PQ/HLG and unsupported wide-gamut inputs fail clearly. Untagged SDR assumes BT.601; output pixels and tags are BT.709.

Actual canonical acceptance renders now produce 1800 frames / 60 seconds at 1080×1920 H.264/AAC with mixed 24/25/60/30000÷1001 footage, genuine display rotation, silent footage and 44.1/48 kHz audio; five decoded markers stay within one output frame. The rich 900-frame / 30-second fixture closes the earlier ducking gap with measured −12.0138 dB, captions at half-open frame boundaries and two crossfades. Browser checks compare decoded normalized-video pixels with independent ffmpeg frames, verify exact download checksum, and reopen persisted history. Detailed source evidence and its limitations live in `.superpowers/sdd/2026-10-09-capy-roadmap/B4-report.md`. Actual packaged-runtime validation remains a separate controller gate; source tests do not establish fresh-install font/binary availability.
